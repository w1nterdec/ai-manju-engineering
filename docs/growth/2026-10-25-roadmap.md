# 以实际证据推进的成长路线

日期：2026-10-25。依据：[0.8.2 审查](../audits/2026-10-25-project-review.md)。以下版本、样本规模与验收条件均为候选计划，不是已交付能力、排期承诺、现有成绩或市场数据。

## 路线原则

先完成连续漫剧的一个真实闭环，再扩大模型与业务。保留零依赖编辑核心、稳定 ID、快照和人工复核边界。项目长期可成为模型之上的制作与质量控制层，其价值需通过真实读音、剧情、连续性与返工证据验证。

业务顺序维持 series_drama → ad_batch → client_service → shoppable_export；前者通过实际证据后再逐步增加后者的范围。已有模板不删除，新增功能暂缓铺开。真实服务调用仍由使用者在自身授权环境执行，开发代理不索要或使用密钥、不进行付费生成。

## 候选 0.8.3：可信素材与交付边界

优先任务是修复本轮 A1–A4：素材原子发布、画像保留文件名、逐任务额外素材依赖、打包来源摘要核对。

退出条件：四个复现变成有针对性的回归测试；中断可重试，非法画像在创建目录前失败；替换参考只重建相关下游；产物被改写时打包拒绝；96 项既有测试和全部 README 示例继续通过，Windows/Linux CI 通过。

投入边界：完全可离线推进，不依赖真实素材、密钥或供应商。没有理由等待人工输入后才修这些问题。

## 候选 0.9：从 mock 记录走到本地实媒

建议增加：

- 统一媒体导入清单，以镜头/台词 ID 关联用户自己的音视频；自动测量与计算摘要，生成来源和审核草稿，但所有人审结论默认 pending。
- `doctor` 类诊断入口，只报告 Python、路径、可选 ffprobe、输出权限和缺失字段；不读取或打印凭据内容。
- 由本地确定性工具生成小型几何画面/PCM 测试素材，验证真正的视频探测、SRT、交接、包校验和损坏输入；这些样本不是漫剧效果评测。
- 可安装的 CLI 与资源分发，验证在仓库目录外运行及安装后的模板发现；核心继续标准库，可选媒体工具独立检测。

退出条件：从干净安装到首个本地实媒交付记录能复现；至少一个真实编码视频经过 ffprobe 路径，缺工具时明确降级；缺授权、人审或关键来源仍阻断生产包。不能把合成技术样本标成客户成片。

这一步仍可零生成费用完成。目标软件的实际导入、人物读音与视觉效果另行人审，不被技术样本替代。

## 候选 0.10：只接一个有明确中文读音控制的 TTS

按确切模型、音色、语言、接口与官方文档日期选择候选，不按品牌或宣传排名选“最好”。先实现请求映射、能力拒绝、输出与任务 ID 留痕、超时查询和取消，再由使用者独立进行实际调用。

接入前的必要改造：

- 将 offline、mock、模拟审核许可分开建模，避免将离线实际媒体误当成模拟批准。
- 将 mock 计费与真实账单记录分开。提交不确定、已预留、待核账和实际费用要有明确状态；真实已发生账单应如实记录，超支时阻止后续调用，不能通过拒绝记账掩盖费用。
- 显式网络开关、有效预算、绑定当前输入的 dry-run 缺一不可；拒绝未知或过期的关键计价/能力配置。
- 用本地 HTTP 假服务和失败注入验证重试、幂等、密钥脱敏与恢复，普通 CI 不调用真实服务。契约变更需版本化和迁移验证。

建议先编制 30 条作者确认的姓名/术语样本，包含多音姓氏、句中连读、称呼和情绪。30 是拟定测试规模，不是已有样本结果。验收按每次姓名出现计数，逐次试听；不通过的名字阻断样本发布。ASR 文本一致不等于读音正确。

实际生成由使用者在授权环境执行，保留所有尝试、失败费用、时间戳和人工结论。本轮审查未调用该类服务。

## 候选 0.11：一条受控视觉链

先固定一组有授权的角色/服装/道具参考，再接一个图像编辑或参考图工作流，以及一个图生视频工作流；也可先导入外部手工制作的媒体。不得为了“支持更多模型”绕过输入和验收边界。

退出条件：同一故事的少量连续镜头在身份、衣着、道具、方位和剧情事实上逐项验收；人物或参考变更能够正确重建；一次局部返工不会重跑无关镜头。关键文字可采用审核后的后期叠加，复杂动作通过拆镜表达。

需要同时保留失败样本和返工次数。图像嵌入相似度可辅助筛查，不能单独证明角色一致或肢体正确。参考图能力的厂商说明不作为本项目成绩。

## 候选 1.0：小团队可复现交付

建议用连续两集原创短片进行试点，并覆盖至少一次执行中断和两次有明确原因的局部返工。这些是拟定验收场景，不是已完成客户案例。

交付证据包括：实际声音与画面、字幕和剪辑交接、全部尝试、供应商任务与账单、授权、复核、来源索引、最终文件摘要、修改轮次和客户验收。独立操作者应能依据记录复核交付包；多人分工先基于明确文件/任务版本，不急于增加分布式服务。

用同一故事、模型与输入参考做可比较实验，事先定义尝试上限和停止规则。普通提示词、结构化提示词、结构化流程加读音/参考控制的整体比较用于衡量流程；要归因到某条提示词，另做单变量实验。

必须报告原始分母：姓名出现正确数、事实传达数、缺陷镜头数、首次通过数、全部尝试、人工工时和最终合格时长。按币种分开报告全部生成及返工费用；没有合格时长时，单位成本不可计算。不能只展示挑选后的成功片段。

## 开源使用增长

增长入口先解决“第一次运行”和“第一次真实制作”：清楚的诊断、可安装入口、一个完整样本、常见失败与最小返工、明确的外部素材许可。真实样片及大媒体适合通过具有来源与摘要的独立资源发布，不放入源码仓库。

后续观察新使用者是否能独立跑通、卡在哪一步、返工是否减少、问题能否按 ID 复现、贡献是否能通过契约测试。不要把星标数当成客户数，也不根据现有代码推断市场收入。对外试用与邀请需要使用者自行决定，本轮没有联系任何团队或发送推广消息。

## 何时再做看板

只有在真实工作流和状态契约稳定、存在明确的重复只读需求时，复议决策 0009。界面应该减少已观察到的操作成本；当前优先媒体导入和草稿生成，避免用界面掩盖缺少真实链路的问题。

继续不实现 API 转售、多租户 SaaS、订阅计费、直播、店铺连接或平台账号自动发布。

## 下一轮可直接执行的工作

先做 0.8.3 的四个修复与回归测试，再设计 0.9 的本地实媒导入与验证。它们不需要真人密钥。供应商选择、授权凭据和真实成片试听观看属于之后的实际验证输入，不应阻塞当前可离线推进的工程任务。
