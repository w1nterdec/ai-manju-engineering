# 工作流与三条生成线路

本页用于每次实际制作时决定“现在做哪一步、输入什么、得到什么、失败退回哪里”。网站入口核对截至 2026-10-25；账户权限与当前模型能力需要在使用时确认。

## 所有线路共享的骨架

选题与使用权限 → 剧本和设定确认 → 分镜与临时声音 → 角色及场景参考 → 画面生成 → 筛选与局部返工 → 配音字幕和剪辑 → 完整审片 → 导出发布。

这条骨架允许来回迭代。配音密集的内容建议先做临时声音再定镜头时长；动作或音乐驱动的内容可以先试视觉节奏。没有一种顺序适合所有作品。

## motion_comic 图片动态漫

**建议工具：**[豆包](https://www.doubao.com/)或 [DeepSeek](https://www.deepseek.com/)整理文本，[即梦](https://jimeng.jianying.com/)制作图片，[剪映](https://www.jianying.com/)完成动态与声音。

1. **剧本准备。**输入自己的故事与原台词；输出分集节拍和必须传达的事实。自己确认后保留一份原文。
2. **角色与场景。**输入设定；输出经选择的参考图。脸、衣服和道具不对时停在这里修改，不把错误带到整集。
3. **逐镜生图。**输入角色参考、一个画面动作和构图；输出镜头图。核对人物站位和剧情信息。
4. **临时配音与粗剪。**把图片与实际声音放入剪映，确定时长。使用关键帧推拉、平移、局部效果与反应镜头表现节奏。
5. **终剪。**替换确认后的配音，校对字幕，加可使用的音效和音乐。全片复核后导出。

**回退点：**画面身份错回参考图；声音错只重做相应句；节奏不对先改剪辑。不是每个镜头都需要图生视频。

**适合保留的自动化：**提示词分镜包、文件命名、台词与镜头清单、候选和返工记录。不要为了自动化先搭 GPU 集群。

## story_video 参考图到剧情视频

**主工具候选：**[即梦](https://jimeng.jianying.com/)、[可灵中文入口](https://klingai.kuaishou.com/)、[Vidu 中国站](https://www.vidu.cn/)、[海螺国内入口](https://hailuoai.com/video/create)。先选一个；另一个只作有明确用途的备用。

1. **定义镜头任务。**角色、地点、一个主动作、景别和对应台词必须清楚。
2. **制作并批准关键图。**先核对人物、服装、道具和空间；图像参考要主动上传并确认平台实际采用。
3. **做一个代表镜头。**使用所选模型支持的图生视频或参考方式，先验证本片最常见的人物与动作。
4. **保存候选。**保留每次输入、输出、工具和模型版本、费用、结果；选用片段单独标记。
5. **完成其他镜头。**同场戏优先沿用已验证的主工具、参考和风格。工具切换后重新检查一致性。
6. **声音与剪辑。**把选用片段送入剪映，完成对白、音效、字幕与节奏。原生视频声音不能准确说出姓名时，可单独配音并复核相应口型及镜头表达。

**回退点：**复杂互动先拆镜；身份不对回关键图；动作与语义不对回分镜；只有节奏问题先尝试剪辑。不要原样无限重试同一提示词。

**能力边界：**角色 ID 是自己的索引，不能跨平台直接锁定身份。首尾帧、多个主体、LoRA、局部编辑、声音或镜头控制都取决于具体模型，不支持的控制不能当成已经生效。

参考：[即梦逐镜指南](https://jimeng.jianying.com/tools/ai-short-drama)、[可灵多图参考官方说明](https://ir.kuaishou.com/zh-hans/news-releases/news-release-details/kuaishoukelingaituichuduotucankaogongneng/)、[海螺官方国内入口说明](https://minimax.cn/news/s2v-01%E5%8F%91%E5%B8%83)。

## agent_first 一站式 Agent 起稿

**工具：**[小云雀](https://xyq.jianying.com/)；操作步骤以 [Web 官方手册](https://xyq.jianying.com/tutorials/web-manual)为准。

1. 上传剧本，确认分集、画风和创作需求。
2. 复核解析结果，检查原台词和剧情事实是否被改写。
3. 确认全局角色与场景，再进入分集制作。
4. 检查故事板、片段和镜头顺序，单独重拍问题片段。
5. 预览合成结果，核对对白、字幕、声音和衔接。
6. 导出，并在需要时使用剪映完成精剪。

**自己仍要保存：**批准后的原文、角色参考版本、重要提示词、片段选择和修改原因。不把全部制作记忆只留在一次对话里。

**回退点：**解析改了原意回剧本确认；跨集外观漂移回全局资产；单片段瑕疵优先重拍该片段。平台输出完成后仍进行 [质量验收](03-quality-and-repair.md)。

## 什么时候需要 API 或 fork

- 已能手工完成重复流程，且明确知道哪一步最费操作，再考虑自动化。
- 有公开 API 的工具，单独核对开发者注册、能力、计费、任务查询及取消；网页会员与 API 额度不混用。
- 想复用开源创作平台，先查看许可证、维护状态、导出能力和模型依赖，再决定 fork；商业网站不是开源代码。
- 自动化先处理本地文件、提示词包、素材登记和状态，不默认自动发布、自动付费或把人工审核改成模型批准。

本项目当前实际自动化能力以 [根 README](../../README.md)为准。工具网址出现在指南中不代表本项目已经调用该工具。旧版高级能力可查 [工程架构](../architecture.md)。
