# 制作记录与文件组织

记录的目的，是下次能找到正确的参考、知道选用了哪一条片、理解为什么返工。个人可以先用文件夹与 WPS 表格，不必为了记录先部署数据库。

## 一个项目保留什么

```text
我的短片/
  01_剧本与设定/     批准原文、角色表、读音表
  02_参考资产/       人物、服装、场景、道具及来源
  03_分镜与提示词/   分镜表、实际使用的提示词
  04_生成候选/       按镜头保存所有重要候选
  05_声音/           按角色与台词保存配音、音乐、音效
  06_剪辑工程/       剪映工程及相关素材
  07_成片与发布/     导出文件、封面、发布记录
  08_记录/           尝试、费用、选片、审核和返工
```

这是推荐的手工组织方式，不要求每个外部平台按相同目录导出。使用本项目自动化时，以它实际生成的目录和说明为准，不要把示意目录当作已存在的产物。

## 命名先保持可辨认

```text
S003_image_v01.png
S003_video_take02.mp4
L005_voice_v03.wav
episode01_cut_v02.mp4
```

镜头编号与台词编号尽量不随文本修改而变化。把最终选用版本写入清单，不能仅依赖“final”“最终”“真的最终”这样的文件名。已有文件不要直接覆盖。

## 三张最小清单

### 角色与读音表

| 字段 | 要记录的内容 |
| --- | --- |
| 角色编号与姓名 | 稳定编号、完整姓名及常用称呼 |
| 确认读音 | 作者指定读法；不确定时标待确认 |
| 参考版本 | 人物与服装文件名，选定日期 |
| 声音 | 工具、音色或录音人员，版本 |
| 来源 | 原创、许可记录与使用范围 |

### 镜头清单

| 字段 | 要记录的内容 |
| --- | --- |
| 镜头与台词 | 镜头编号、关联原文和说话人 |
| 画面任务 | 观众应知道的事实与主要动作 |
| 输入 | 角色、场景和道具参考版本 |
| 生成 | 实际工具、模型、提示词、日期 |
| 候选与采用 | 候选文件、选用版本、选用理由 |
| 状态 | 待制作、待审核、待返工、选用、弃用 |

### 尝试与返工表

```text
镜头：
本次输入版本：
工具与模型：
输出文件：
采用 / 弃用 / 待审核：
错误类型与具体时间点：
本次费用：金额与币种 / 待核账 / 模拟
已尝试次数：
下次只改什么：
其他需要重查的内容：
```

没有获得实际费用时写“待核账”，不能填 0。网页积分和人民币不直接相加；只有当前套餐的换算依据明确时才另做估算。试用、会员和 API 分开记录。

## 每次制作结束前做这五步

1. 从外部平台下载本轮决定保留的媒体，核对下载文件确实可播放。
2. 保存实际提示词和参考版本，不只保存修改前的模板。
3. 在镜头清单上明确选用片，旧候选保留或标记弃用。
4. 更新实际费用、问题原因和下一步，未审核继续写待审核。
5. 备份剪辑工程与必要素材；复制工程前核对是否引用了项目目录外文件。

## 自动化最值得先处理的事情

- 从一份批准原文生成分镜制作包、提示词草稿和工具跳转地址。
- 批量创建可辨认的目录和清单，降低手工遗漏。
- 登记候选素材、查看下一步和导出待返工清单。
- 对有明确接口的工具接入请求、查询与结果登记。

本地记录不能证明实际画面正确。API 自动化还需处理超时、重复提交、费用和取消，不能用网页会员直接推断已具备这些能力。进阶工具的实际状态以 [根入口](../../README.md)与 [工程说明](../architecture.md)为准。
