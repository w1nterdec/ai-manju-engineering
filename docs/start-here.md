# 新手到工程实践

## 第一个目标：完成一个可验收的镜头

先用《午夜来信》的 S001，长度与画幅只是起点，可以调整。不要一开始制作整季。工具尚未选定时，先按能力选型：图像工具需要参考图或编辑能力；TTS 需要明确的读音控制或可稳定试听纠音；视频工具需要支持已批准图像作为输入。提供试用并不代表最终成本更低，应记录返工次数。

1. 阅读原剧本、两名角色设定及姓名词典，确认自己知道每个名字怎样读。
2. 用 [角色设定提示词](../prompts/02-character-bible.md) 制作正面、侧面、三分之四视角参考图，人工选定同一身份的一组图片。
3. 生成 S001 的双人静态关键帧，核对画左、画右、右手、信封数量与服装。
4. 固定两名角色的音色，先只合成 L001：“乐知遥，这封信是你放的？”逐句试听，确认姓名和语气。
5. 用已批准关键帧生成短镜头。按实际模型时长调整计划，避免为了塞进原定时长过度加速声音。
6. 剪辑声音与视频，按实测声音重新对齐字幕，完整观看，再填写复核记录。

第一轮建议分离声音和画面生成：这是为了让名字、声音和镜头能独立返工。选用原生音视频联合生成工具时，同样应按实际能力验证读音，必要时替换配音并重新处理口型。

## 不写代码也可以使用

按 [提示词目录](../prompts/README.md) 顺序复制模板，把占位符替换为自己的设定。每一步先人工批准再进入下一步。最终台词、角色身份和剧情事实保存在自己的项目文件中，避免对话窗口里多个草稿互相覆盖。

## 使用工程工具

在仓库根目录打开终端：

```bash
python -m manju init my-episode.json
python -m manju check my-episode.json
python -m manju build my-episode.json --out build/my-episode-v1
```

`init` 复制完整原创例子，编辑名字时要同步更新词典，不要改角色 ID。修改台词只改 `beats[].lines[]`，分镜中的 `line_id` 保持引用。

常见检查结果：`E004` 是不存在的引用，`E006` 是状态不连续，`E010` 是节拍或台词遗漏。全部错误须修复后才能构建；警告需要人工判断。退出码见 [数据契约](data-contract.md)。

## 扩展到多集

参考 `examples/midnight_letter/series/`：`canon.json` 保存全剧角色、读音与风格，各集通过 `canon_ref` 引用。每集仍可独立检查和构建，系列检查会核对共享设定内容及跨集状态。后续真实生产应逐镜头分配任务，不要让单次模型调用承担整季剧情。

## 选择什么题材

从角色少、场景少、动作简单的短片开始更容易定位错误。熟悉流程后，再按 [题材手册](genre-playbook.md) 增加关系状态、战斗空间、笑点节拍或世界规则。困难可以逐步增加，验收规则始终保留。
