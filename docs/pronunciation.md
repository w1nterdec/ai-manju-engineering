# 中文姓名与术语的读音工程

## 先区分四件事

姓名汉字、作者指定读音、TTS 实际发音、字幕文字是不同对象。`pronunciation_lexicon` 保存作者指定的目标；只有试听实际文件，才能确认本次声音达标。拼音登记本身不是发音评测。

项目使用数字声调拼音表达编辑意图，例如 `单行舟 → shan4 xing2 zhou1`。这不是任意 TTS 通用的请求参数，也不是完整音系校验器。轻声用 5；ü 可记录为 v 或 u:，由适配器转换。连读、变调、方言和艺名须结合上下文试听，不能只按字典单字音判断。

## 建议顺序

1. **建立词典**：完整姓名优先；另收录称呼、别名、地名、生僻字、专业术语和同字不同音的词。角色读音由作者确认，不能假设姓氏只有一个读法。
2. **能力检查**：所选接口究竟支持发音词典、音素、SSML、拼音纠音还是纯文本？必须查到对应模型、音色与接口的支持范围。禁止让不支持的接口静默忽略控制项。
3. **小样验收**：用完整姓名、他人称呼、激动喊名、句中连读各做小样；固定音色版本后才批量生成。
4. **逐句生产**：保留原文、实际请求、音色 ID、模型 ID、参数、文件摘要和试听结论。只重做出错句，再检查拼接处语气和音量。
5. **字幕独立**：从 `text` 输出字幕。`speech_text` 仅用于已批准的声音输入调整；不要把用于纠音的同音字写进字幕。

## 支持发音控制时

[微软语音官方文档](https://learn.microsoft.com/zh-cn/azure/ai-services/speech-service/speech-synthesis-markup-pronunciation) 说明了音素、别名和自定义词典机制；具体语言和音色的支持范围需要继续查对应表格。[阿里云实时语音合成文档](https://help.aliyun.cn/zh/model-studio/realtime-tts-user-guide) 介绍 `hot_fix` 纠音，并要求根据实际模型 API 配置。不要把同一套 SSML 或拼音格式直接发送到所有供应商。

本版本仅导出 `pronunciation_hints`，没有调用这两个服务；具体请求转换与合成实测属于后续适配器工作。

## 只支持普通文本时

可尝试更明确的完整上下文、分句或经过试听的局部同音替换，但这是降级手段，容易改变韵律或含义。任何替换都应保存 `text` 和 `speech_text` 的差异并人工批准。反复读错的名字应考虑更换支持发音控制的工具，不要持续堆叠“绝对不能读错”的指令。

不要直接把括号里的拼音追加到配音正文：有的工具会把注释一起读出来。纯文本里加情绪括号也可能被念出，应先核对工具支持方式。

## ASR 和口型

ASR 可辅助发现缺句、漏字、串台和文本偏差，无法可靠证明指定字音正确：同音姓名可能被正常转写，错误读音也可能被语言模型纠回原文。最终仍需母语者或具备相关语言能力的审核人试听；必要时增加音素级检测，但其结果也要验证。

声音时长确定后再做字幕对齐、口型或相应剪辑。修改配音会使原字幕时序、口型和混音复核失效。当前工具没有自动对齐、口型生成或音素评分功能。
