# 架构与扩展边界

## 已实现的执行路径

`共享设定 / 独立剧本 → 解析与静态检查 → 冻结快照与计划编译 → 手动调用生成工具 → 绑定实际媒体的人工复核记录`

- `manju/project.py`：共享设定展开与系列检查。
- `manju/validation.py`：结构、引用、节拍、对白时序与状态链。
- `manju/build.py`：确定性计划编译；临时目录完成后改名，避免展示半成品构建。
- `manju/review.py`：构建完整性、逐镜头复核与媒体摘要匹配。
- `manju/providers.py`：未来供应商接入所需的最小 Python 契约；当前没有任何真实实现。

核心逻辑不依赖供应商 SDK，不需要付费调用即可验证输入和计划。首版以 JSON 文件和命令行为边界，方便手工使用、版本管理和后续接入工作台。

## 数据的唯一来源

系列级设定保存人物、读音、画幅、风格与世界事实；单集保存节拍、原始台词和分镜。台词不在分镜中重复保存。构建快照是一次制作计划的冻结版本，后续修改源文件不会悄悄改变已生成计划。

为当前源文件验收时，`gate` 应始终提供 `--source`；这样剧本和共享设定的任何字节变化都会使旧复核失效。未提供时，仅检查冻结构建。版本 0.1 采取保守的整集失效策略，包括纯格式变化。

同一输入内容和同一工具、模板版本在同一环境下生成确定的文本字节。清单不写动态时间戳。不能因此声称远端生成模型输出可确定重现；真实适配器仍须记录模型、参数、供应商任务和实际媒体。

## 大型项目的目标结构（后续建设）

保持“系列 → 季 → 集 → 场 → 镜头 → 资产版本”层级。角色身份、服装、音色、场景、道具、剧情事实都应使用稳定 ID 和显式版本。所有资产同时保留来源、摘要、授权与审查记录，避免文件名成为唯一身份。

计划执行器以任务 DAG 分配工作：关键帧批准后才能生成视频；实际声音确定后才能对齐字幕与口型；相关人工复核通过后才能组装剪辑。跨集依赖、声音对齐、口型和混音尚未进入当前粗粒度 `tasks.json`，正式执行器必须补充这些节点。

执行层后续需要：

- 持久化任务状态及追加事件：planned、queued、running、succeeded、failed、cancelled。
- 幂等键和供应商任务 ID；提交成功而客户端超时后，先查任务再决定是否重提，避免重复扣费。
- 任务预算、并发上限、限流、最大重试、可取消运行及失败隔离。
- 内容寻址资产和依赖失效：从失败镜头或变化输入重新计算，不重跑整季。
- 角色、导演、声音审核、画面审核等工作分工及变更审查；审核决定绑定具体媒体摘要。
- 多人协作时使用数据库、对象存储与权限模型；单机时保留当前本地文件路径。

不要在完成实际多集样本之前引入微服务数量或基础设施规模作为质量指标。接口和数据边界可扩展，吞吐与成本需要负载测试证明。

## 关键决策

1. 模型无关的编辑意图，与供应商的控制语法分离。不能支持的关键约束显式失败。
2. 静态检查只证明结构与已声明状态；语义质量与媒体质量单独验收。
3. 构建目录不覆盖，摘要绑定审查，防止复核结论误用于新文件。
4. 不把演示生成的虚构成绩写入评测报告；基准必须保留真实样本和计算方法。
5. UI 是未来消费者，不能成为维护项目数据的唯一通道。
