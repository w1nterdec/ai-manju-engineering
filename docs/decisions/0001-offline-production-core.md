# 0001：离线优先、增量扩展与画像顺序

日期：2026-10-24。状态：采用。

背景：0.1 只有计划编译与人工记录，没有执行、成本、授权或交付。用户授权 M0–M8 自治开发，但禁止付费调用、泄密、直接推主分支和未经验证的能力宣传。

备选方案：重写整套框架；直接绑定某厂商；在现有零依赖包上增加版本化生产侧文件。

选择：保留 episode 0.1 和现有 CLI/构建格式，新能力使用独立的配置、计划和运行契约。先实现 series_drama，再 ad_batch、client_service、shoppable_export。后几种画像复用执行、预算、资产和交付机制，避免为每种模式写独立流水线。

执行顺序保持 M0→M1→M2→M3→M4→M5→M6→M7；预算将在真实适配器出现前完成，任何非 mock 执行均要求网络开关、显式预算和绑定输入摘要的 dry-run。M8 只在前序稳定后评估，默认优先审计与交付能力。

影响：开发中只使用确定性 mock 占位产物。占位资产、音频静音和模拟成本不得作为实际成片或法律授权证据。生产交付与演示交付必须分别标记。

回滚：切回 milestone-M0 或旧 main；新侧文件不影响旧的 episode/build/gate 命令。已推送修改只用追加提交修复。

不确定度：中；并发、超时与供应商幂等尚无真实集成样本。复核触发条件：选择真实供应商、开始多人并发写入或取得真实成片评测资料。
