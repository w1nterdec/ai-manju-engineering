# 0011：以实媒证据而非接口数量驱动成长

日期：2026-10-25。状态：采用路线原则；候选版本尚未实施。

背景：0.8.2 的离线契约和既有测试通过，但没有真实生成/客户证据，本轮另复现四个 P2 边界问题。继续增加 mock、画像或看板不能回答最初的读音、画面与剧情问题。

备选：扩大模型聚合与前端；重写服务架构；修复边界后逐步完成实媒、单 TTS、单视觉链和小团队试点。选择第三种，保留现有零依赖核心和数据边界。

顺序：候选 0.8.3 修复 A1–A4 → 0.9 本地实媒导入/分发 → 0.10 中文纠音 TTS → 0.11 参考图与视频 → 1.0 有真实证据的试点。版本号是计划标签，不是排期或质量承诺。业务仍以 series_drama 优先，其余画像保留而暂缓扩展。

影响：真实适配器之前需要显式区分 offline/mock、真实计费与未知账单，并保留网络开关、预算和 dry-run；不简单移除当前拒绝真实调用的分支。开发代理不使用真实密钥或发起付费生成。

回滚：只调整路线文档，不改变运行时或既有契约。若真实样本证明不同瓶颈，应以证据重排阶段，保留决策来源。

不确定度：高（实际声音、画面、费用和客户操作尚未测量）。复核触发条件：首个真实闭环、可重现的实际费用、外部使用反馈或关键供应商能力变化。
