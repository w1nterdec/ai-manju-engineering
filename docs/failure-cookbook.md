# 常见故障与最小返工

## 名字读错、串音色

先区分读音字典缺失、接口不支持、音色本身不稳定、请求被错误清洗和合成后人工未听五类原因。保留错误句的实际输入与输出；只改读音控制，固定其他条件重测。若是音色混用，检查角色 ID 到音色 ID 的绑定。修复后重新试听整句及邻句连接，再更新字幕和混音。

## 换脸、换衣、道具漂移

建立经批准的多视角人物参考和服装版本；从批准关键帧开始变化。镜头逐渐增加复杂度：单人静态 → 单人简单动作 → 双人互动。固定 seed 只能在特定实现和参数下提供部分可复现性，不能作为跨镜头身份保证。

参考图也可能失效或被过度复制，需检查机位变化、面部特征、遮挡和服装细节。局部服装错误先做局部编辑；关键帧一旦改变，应重新评估依赖它的视频镜头。

## 肢体瑕疵、穿模、动作断裂

优先减少复杂手部互动、主体数量和同一镜头里的连续动作；使用更清楚的构图、姿态参考或可控工作流。只安排“拿起信封”比同时要求拿起、拆开、阅读、转身、争吵更易审核。必要时通过特写、反应镜头和剪辑表达动作，不强求一条生成视频完成全部过程。

检查首帧、尾帧、动作关键点，并完整播放中间过程；仅看封面不能发现视频内的肢体突变。静帧通过不代表其生成视频通过。

## 剧情漏项、人物知道不该知道的信息

每个节拍记录必须传达的事实、人物的已知信息及其来源。检查台词分配后，再人工核对事实是否真正表现出来。人物提前得知秘密、因果动机改变、事件先后颠倒等属于语义问题，当前静态检查器不能自动理解。

状态字段用来表达关键连续性：道具归属、门是否关闭、服装版本、人物伤势、关系或已经得知的信息。字段由项目作者显式定义；检查器只能比较字符串，不知道某个动作是否足以产生该状态变化。

## 日期、招牌、信件文字错误

关键叙事文字优先通过后期叠字、跟踪或已审核素材合成。保留可编辑文字层，重新检查遮挡和透视。对钟面、手机界面、屏幕数字也采用相同策略。

## 声音和视频不同步

先测配音真实长度，再调整停顿、镜头长度和剪辑点。字幕按最终音轨对齐。需要正面对白时，再做口型处理和嘴部特写复核；画外音、背影、反应镜头也是合法叙事方法，但应在剧本中明确使用，避免意外遗漏说话人。

## 返工影响范围

- 修改名字的读音：重做相关台词，复核字幕时序、口型、混音和最终剪辑。
- 修改角色外观：检查所有依赖该外观版本的关键帧与视频。
- 修改剧情事实：重查关联节拍、台词、状态链和后续依赖剧情。
- 修改某镜头音乐或音量：复核混音衔接；如未改画面，不必自动重做全部图像。

旧 `tasks.json` 是计划；0.8.2 离线执行器已实现基于任务键的局部失效与恢复，仍只内置 mock，且有四项历史边界待修。个人跨网站制作时按[局部返工指南](creator-guide/03-quality-and-repair.md)人工确认影响范围；不要认为本地改记录会自动重做网站素材。具体工程范围见 [架构](architecture.md)。
