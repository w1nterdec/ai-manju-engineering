# 质量验收与人工复核

> 本页属于可选工程参考。个人实际制作先读[创作指南](creator-guide/README.md)；原有 mock 或接口契约不表示真实平台已接通。

## 制作阶段

剧本冻结后分别验收声音、关键帧、视频、逐镜头组合与最终成片。每个阶段给出明确的缺陷定位和返工决定，避免用单个“画质分”抵消名字错误或剧情漏项。

当前实现两层工具：`check` 检查编辑计划；`gate` 检查冻结构建的逐镜头人工记录与媒体摘要。声音合成、视频观看、媒体格式探测、字幕实测对齐、最终成片技术验收仍需要手动完成或由后续工具实现。

## 四项逐镜头检查

- **pronunciation**：逐句试听；姓名、术语、缺字、串音色均需检查。有对白时必须 `pass`，无对白时可填 `not_applicable`，并说明原因。
- **visual**：观看完整镜头；人物身份、服装、肢体、遮挡、道具、文字、首尾帧与中间变化均需检查。
- **story**：逐项核对 `required_facts`、人物已知信息、台词语义与状态变化是否真正表达。
- **timing**：核对最终声音、镜头长度、停顿、对白衔接和字幕时序。计划时间不能代替实测。

每项用 `status` 与具体 `note` 记录，不接受只有“通过”而没有说明的空字段。工具只能检查说明非空，无法验证审核人是否认真观看。

## 操作流程

1. 构建到新目录，例如 `build/demo-v1`。
2. 创建 `review.json`；模板默认全部 `pending`。
3. 把经过实际制作的媒体放入该构建目录的 `media/`。每镜头一个 video，有对白时另提供一个实际配音/对白混合 audio。路径相对构建目录，禁止越界。
4. 使用 `python -m manju hash 文件路径` 得到 SHA-256，写入对应 `artifacts[].sha256`。
5. 审核人试听和观看这些确切文件，填写姓名或项目内身份、带时区时间，例如 `2026-10-24T15:30:00+08:00`，以及四项结论和证据说明。
6. 执行 `python -m manju gate 构建目录 复核文件 --source 当前剧本`。

缺失记录、待审核项、被修改的计划文件、摘要不匹配的媒体、改变的源剧本或共享设定都应使检查失败。修改媒体后应实际重新审核，再更新摘要；单纯刷新摘要不能证明新文件合格。

## 验证边界

`gate` 不是签名、身份认证或防篡改审计系统；有写权限的人可以同时改文件与清单。它用于防止普通工作流中的过期记录和误用版本。多人生产部署需补充权限、审批、可信时间、不可变存储和事件记录。

工具不会解码媒体或判断文件扩展名是否反映真实内容；测试中的模拟字节只验证程序分支，不是合格成片。音轨与视频的实际对应关系由审核人确认。当前也没有审核最终整集文件，因此逐镜头记录完整后，仍必须验收最终剪辑、字幕、混音、转场和内容素材权利。

是否公开作品是独立的发布动作。本工具不自动发布媒体。
