# 四种画像与参数化成本

画像是 configs/profiles 下的版本化 JSON；new 按其中的交付物、检查、指标和模板创建项目，没有按业务 ID 写死四条流水线。自定义画像可传文件路径，必须通过相同校验。

- series_drama：每合格分钟、每集；保留人物/道具跨集连续性检查，实际系列检查使用旧 check-series。
- ad_batch：每条、每 SKU、每变体；商品资料和多个 hook 形成有父输入摘要的变体，CSV/JSON 输入，单项失败不阻断后续。批次共用预算账本，运行结果分项目/集/镜头/批次核算。
- client_service：生成成本＋工时×时薪，加使用者填写的返工缓冲；以 margin 计算售价 = 含缓冲成本 / (1 - margin)，不是简单加价率。修改轮次、请求人、验收单均有模板。
- shoppable_export：每条成片；仅输出 SKU、HTTPS 商品链接和成片内时间点，不连接店铺、支付或发布 API。

所有成本、缓冲和利润参数由使用者填写，不提供市场价格或盈利结论。DEMO 示例只验证公式。零合格时长/数量不能计算单位成本；未知不能当作零。

批次暂不提供整个批次的自动恢复命令；单项 run 可按已有执行器继续恢复。批次开始使用新目录，batch.json 在单项结束后原子更新；未完成项需使用新批次版本或逐项运行。实际商品与画面一致性仍需人审，不能从 SKU 元数据存在推断画面正确。
