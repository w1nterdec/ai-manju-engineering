# AI虚拟制片平台升级计划书

版本 V2.0  日期 2026-10-25  时区 Asia/Singapore

**计划周期：2026-10-25 至 2026-11-04。最终交付必须早于用户确认的 2026-11-05 续费／到期日。**

## 1 项目目标与交付边界

本计划将现有 AI 漫剧提示词工程升级为可验证的本地制作试点版。以已有剧本契约、任务依赖、预算、资产血缘和审核门禁为基础，在固定期限内完成真实素材进入、确定性合成和可复核交付；轻量工作台按完成情况增加。

| 事项 | 本周期约定 |
| --- | --- |
| 计划起止 | 2026 年 10 月 25 日至 11 月 4 日 共 11 个日历日 |
| 最终交付 | 目标 11 月 4 日 18 时 最晚当日 23 时 59 分 |
| 订阅节点 | 用户确认 GPT Plus 于 11 月 5 日续费或到期 |
| 时间口径 | Asia/Singapore UTC+8 不依赖 11 月 5 日的具体扣费时刻 |
| 交付定位 | 单机 单用户 本地制作试点版 |
| 组织方式 | 项目负责人提供制作判断 Codex 在交互会话中辅助研发 |

### 本周期成功标准

能够把一组按镜头和台词关联的真实音视频导入项目，完成测量、审核、字幕、基础合成和交付校验，并演示一次局部修改与一次中断恢复。视频与配音允许在外部工具制作后导入。

优先样片为 30 至 60 秒、5 至 8 个镜头、2 个主要角色、1 个场景的原创短片。实际素材缺失时，交付明确标注的技术验证样本与软件，不把几何画面、静音或 mock 记录当作真实漫剧效果。

### 相较上一版的优化

将原 12 至 16 周 MVP 调整为 11 天交付窗口；取消新建多语言微服务、完整前端、视频模型池和分布式基础设施的首版要求。当前周期保留完整平台路线，交付目标聚焦可复现的本地生产闭环。

计划状态为待实施。工程验收、真实效果与商业交付分别留证；任务完成以本周期的实际运行、审核和交付记录确认。

## 3 生产流程与最小技术方案

### 一次制作的操作顺序

确认剧本与角色参考，冻结分镜；在外部制作或录制画面与配音；按稳定 ID 导入；测量音频和视频；生成审核草稿与实测字幕；人工选定镜头；执行基础合成；复核成片；生成交付包并独立校验。

剧本拆解可借助当前对话中的 AI 生成草稿，再导入现有数据契约。本周期不把平台内嵌 LLM、Codex SDK 或自动多 Agent 服务作为必需依赖。

### 组件与职责

| 组件 | 本周期设计 |
| --- | --- |
| 生产核心 | 保留现有 Python 与 CLI 不重写已有预算 审核及交付内核 |
| 媒体导入 | 薄层命令或表单草稿工具 校验本地文件并关联镜头 台词与资产 |
| 媒体工具 | 显式检测 ffmpeg 与 ffprobe 由使用者在授权环境准备 |
| 数据与文件 | 沿用单机 SQLite 单写入与 JSON 契约 媒体使用本地目录 |
| 合成执行 | 采用固定参数生成参数数组 调用受控媒体工具 不执行模型任意脚本 |
| 可选界面 | 从现有 JSON 与报告读取数据 默认本地只读 |
| 后续服务化 | 多人或多机需求成立后 再评估 FastAPI PostgreSQL 对象存储 |

### 数据规则

沿用 project、episode、shot、line、character 的稳定 ID。导入记录至少包含关联 ID、文件摘要、实际时长、来源、批准状态和用途；候选素材保留版本，选用版本单独记录。新增侧文件独立版本化，不静默修改 episode 0.1。

参考或台词变更后，仅使实际依赖它们的下游结果失效。旧审核不自动继承到新媒体。offline 与 mock、技术通过与人工批准、演示与生产分别表达，避免把本地真实媒体误归类为模拟审核。

### Codex 的使用位置

用于任务拆分、适配与合成代码、针对性测试及文档。项目状态和审核结论由确定性代码与负责人维护；本周期不建设长期自治调度中枢，也不在没有新会话或自动化安排时承诺持续后台开发。

## 5 工程工作包与改动边界

### 工作包 A 修复可信素材与交付边界

围绕 assets、business、planning、delivery 等现有模块处理四项问题：素材临时写入后原子发布，画像保留名提前拒绝，额外素材按任务进入参数与失效键，打包前后核对声明产物及血缘摘要。每项增加直接证明恢复或拒绝行为的回归，不保留要求缺陷存在的断言。

### 工作包 B 本地媒体导入与诊断

输入是媒体清单和本地文件，输出是按镜头及台词关联的导入记录、摘要、测量值和 pending 审核草稿。缺文件、重复绑定、路径越界和媒体损坏时明确失败。诊断只检查工具、权限、路径和缺失字段，不读取或打印凭据。

### 工作包 C 基础合成与交接

只支持一种确定的交付规格，建议 9 比 16、1080p、MP4 H.264 视频与 AAC 音频；实际帧率和响度参数在首次验证后固定。先支持镜头顺序拼接、实际配音和字幕，不做复杂特效、自动配乐或口型保证。音乐仅使用已提供且可使用的素材。

采用实测时间线检查视频是否覆盖对白。需要延长或重新剪辑时，先明确冲突，不靠拉长字幕掩盖画面时长不足。保留可供外部剪辑工具复核的时间线和来源索引。

### 工作包 D 验证与交付

用真实编码技术样本验证媒体路径，用原创媒体验证制作效果，两类证据分开。保留至少一次中断、一次素材或台词变更及对应重跑记录。交付包附环境诊断、操作步骤、审核状态、来源清单和已知限制。

### 兼容与质量约束

保留旧 CLI、episode 0.1 和已有构建目录的不覆盖约定。可选依赖及媒体工具不强制进入标准库编辑核心。优先运行改动对应的测试，交付前完成完整适用测试、README 示例验证和差异检查；未运行项记录原因，不以历史通过代替本轮结果。

本周期不变更远端权限，不自动发布平台，不采购算力或模型，不把计划书等同于代码实施或外部付费授权。

## 6 验收清单与交付物

验收逐项记录输入、操作、预期结果、实际结果和证据位置。技术通过只代表该项检查成立，角色一致性、读音与剧情表达仍由负责人观看和试听。

| 编号 | 验收场景 | 通过条件 |
| --- | --- | --- |
| A01 | 四项既有边界 | 修复各有针对性回归 原有适用能力无回归 |
| A02 | 真实视频路径 | 实际编码文件经过探测 合成与结果复核 |
| A03 | 媒体导入 | 镜头及台词绑定可追溯 摘要 时长 来源正确 |
| A04 | 字幕与时长 | 字幕保留原文 实测时间线完整 无静默越界 |
| A05 | 局部修改 | 只失效实际相关下游 无关镜头可复用 |
| A06 | 中断恢复 | 不丢已完成记录 不复用损坏产物 |
| A07 | 审核与授权 | 草稿默认 pending 缺必要记录时生产包被拒绝 |
| A08 | 来源与包校验 | 采用文件匹配来源摘要 独立校验通过 |
| A09 | 成本记录 | 未知费用为待核账 模拟数值与实际费用区分 |
| A10 | 复现与说明 | 按说明在干净输出目录复跑 失败提示可操作 |

### 最终交付清单

代码与配置快照；修复及回归结果；媒体导入和合成入口；样片或技术验证视频；来源、审核与时间线记录；独立可校验交付包；启动和操作说明；已知限制与后续待办。P1 成功时另附本地概览或 TTS 验证结果。

### 交付结论分级

P0 技术验收通过且原创素材完整并经人审，可记录为本地制作试点通过；仅有技术样本时，记录为技术验证通过；若 P0 硬门槛未通过，则交付进展快照、失败证据和剩余工作，不标记试点已完成。

本周期只建立工时、采用率、返工次数与成本的测量口径，不承诺三倍提效或客户商业验收。费用按币种分开，未知金额不能当作零。

## 7 资源安排与风险处置

### 人员与输入

按一名项目负责人加 Codex 交互式开发辅助安排，不假设已有 5 至 8 人团队。负责人建议每天预留 30 至 60 分钟处理素材、读音、画面和范围判断，并在 11 月 4 日预留完整验收时段；这属于协作安排，不代表已确认可投入工时。

10 月 26 日前建议准备原创短剧文本、角色设定、可使用的参考与音视频以及来源记录。无法及时准备时，由本地几何画面与音频技术样本保障工程验证，真实艺术效果单列待验。

### GPT Plus 与费用边界

本周期优先利用订阅内可用的开发辅助额度，不默认续费、升级或追加购买。实际可用量受账户状态和使用方式影响，应查看使用面板；本计划不把订阅折算为固定开发工时或连续运行保障。OpenAI 官方定价说明区分订阅用量与 API 用量 [S1]。

视频、TTS、其他模型 API、云存储和算力需按各自服务核算，不能列为已包含在 Plus 的免费预算。主线不依赖付费生成；可选真实验证前由负责人明确服务、币种、总额、单次及重试上限。未知费用单独待核账。

| 风险 | 触发信号 | 处理方式 |
| --- | --- | --- |
| 额度或会话不足 | 关键工作包无法继续 | 优先 P0 取消 P1 保留状态与复现说明 |
| 素材准备延迟 | 10 月 26 日缺主要输入 | 技术样本验证 真实效果待验 |
| 媒体工具不可用 | 10 月 27 日环境检查未通过 | 优先解决工具路径 不启动可选界面 |
| 修复超预期 | 10 月 31 日仍无完整闭环 | 取消 P1 降低样片复杂度 |
| 服务接入不确定 | 权限 计费 幂等边界不清 | 使用外部素材导入 暂不接真实服务 |
| 范围继续膨胀 | 出现新 3D 或多人需求 | 记入下一周期 不挤占冻结后验收 |

### 容量使用原则

将约 7 天投入核心修复与闭环，约 2 天用于完整验证与文档，最多 1 天用于增强，最后 1 天用于验收与缓冲。多人审阅只在能降低关键错误时使用，避免重复扫描、反复全量测试和大范围重构。

## 8 后续演进与执行依据

### 交付后第一步 真实生成与操作工作台

本地试点通过后，按一个中文 TTS、一条参考图到视频路线的顺序接入真实服务。先实现外部任务 ID、请求指纹、超时查询、结果未知、分类重试和费用核对，再增加操作界面。单个供应商不支持幂等时，不承诺绝不重复收费。

### 第二步 小团队协作

有真实分工和重复使用需求后，增加项目角色、服务端授权、版本冲突处理和时间点审片。明确多人写入或多机 Worker 需求后，再迁移服务型数据库和对象存储；不把单机 SQLite 放到网络共享盘作为多人数据库。

### 第三步 轻量虚拟片场

选择固定场景、简化人物和基础机位，输出目标模型实际支持的参考帧或参考视频。比较纯提示词、2D 参考和 3D 预演的镜头符合度、采用率、返工与总成本，证明收益后再投入复杂编辑器。数字演员、UE、商城和企业部署另行规划。

### 阶段进入条件

下一阶段由真实证据触发：本地媒体与交付可复现，才扩展真实生成；生成和费用可追溯，才扩大协作；3D 控制能改善合格镜头产出，才建设完整片场。11 月 5 日后继续开发所需的订阅、工时和预算另行安排。
